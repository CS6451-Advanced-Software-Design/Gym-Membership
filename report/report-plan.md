What each report section needs, what evidence backs it, and who owns it. Sections must appear in this order (spec §1–14). Use this as the checklist before submission. The reasoning behind the quality bar is in [sample-project-lessons.md](sample-project-lessons.md). Owners follow [roles.md](roles.md). The owners for §1, §2, §11 and §14 are proposals, so swap them if the split isn't even.

**Rule for every section: never claim anything the code or the repository doesn't show.** If a pattern, pipeline or test is in the report, a marker must be able to find it in the code.

## Evidence to collect as we go

These are cheap now and impossible to reconstruct in the last week:

- Commit every week under your own account, so the history and the diary agree. A burst of commits on the last day contradicts the diary.
- Log every GenAI prompt in the same PR that uses its output.
- Keep the PMD and CK reports from **before** each refactoring (CI artifacts or a copy in `report/metrics/`). The before numbers are the evidence.
- Each pattern owner writes a test that exercises the pattern itself (e.g. a state transition is refused, the best discount wins, a waitlisted member is promoted).
